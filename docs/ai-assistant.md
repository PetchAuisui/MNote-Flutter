# AI Assistant (Gemini Chat)

เอกสารนี้อธิบายฟีเจอร์ผู้ช่วย AI ใน Mnote: ปุ่ม AI (ไอคอน `auto_awesome`) มุมขวาบนของหน้าแก้ไขที่เปิดแชทคุยกับ Gemini และแนบโน้ตที่เปิดอยู่ให้ AI อ่านได้ ทำอะไรได้ ใช้วิธีไหนและเพราะอะไร ข้อมูลไหลผ่านไฟล์ใดบ้าง ความปลอดภัย การทดสอบ สิ่งที่ตั้งค่าใน Firebase Console ใครใช้ AI ได้บ้าง และถ้าจะต่อยอดต้องทำอย่างไร

- Branch: `feature/ai-chat` (แชท, PR #31) และ `feature/ai-note-context` (แนบโน้ต)
- ตอบโจทย์อาจารย์ข้อ "ใช้ AI อย่างน้อย 1 Feature (Gemini API)" และเป็น Firebase บริการที่ 3 ของโปรเจกต์ (ต่อจาก Auth และ Firestore)
- สถานะ: Android ทดสอบบนแท็บเล็ตจริงแล้วทั้ง debug และ release, iOS ทดสอบบน iPad แล้ว (debug + debug token), การแนบโน้ตทดสอบบนแท็บเล็ตครบ 9 กรณี (หัวข้อ 9), CI ผ่านทั้ง Android และ iOS build

> **ก่อนเทสหรือ demo อ่านหัวข้อ 7.5 (ใครใช้ AI ได้) และ 7.6 (โควตา: ทั้งทีมได้ 20 ข้อความต่อวัน)** และคนดูแล Firebase อ่านหัวข้อ 7 ทั้งหมด

## 1. ปัญหาและแนวทาง

ทีมต้องการให้ผู้ใช้คุยกับ AI ได้ทันทีที่เปิดแอป **โดยไม่ต้องไปสมัครหรือหา API key มาใส่เอง**

| ทาง | ผล |
|---|---|
| ให้ผู้ใช้ใส่ Gemini API key เอง | ไม่เลือก: ยุ่งยาก ผู้ใช้ส่วนใหญ่ไม่มี key |
| ฝัง API key ไว้ในแอป | ไม่เลือก: **อันตราย** repo เป็นสาธารณะ และใครก็แกะ key ออกจากไฟล์ APK ได้ |
| ทำเซิร์ฟเวอร์ (Cloud Functions) ถือ key เอง | ปลอดภัย แต่ต้องใช้แผน Blaze (ผูกบัตร) และเป็นงานใหญ่ |
| **Firebase AI Logic** (เลือกใช้) | key อยู่ที่ Firebase แอปเรียกผ่าน SDK ใช้แผน Spark (ฟรี) ได้ และอยู่ในโปรเจกต์ Firebase เดิมของทีม |

งานนี้ใช้โปรเจกต์ Firebase เดิม `mnote-8db27` **ไม่ได้สร้างโปรเจกต์ใหม่ และไม่ได้รัน `flutterfire configure`** จึงไม่กระทบ config ของ Auth/Firestore

## 2. ความสามารถ

### 2.1 ปุ่มเปิดแชท

ปุ่ม AI (`Icons.auto_awesome`) อยู่หน้าปุ่ม "ส่งออก" ที่มุมขวาบนของหน้าแก้ไข

| ขนาดจอ | รูปแบบ (Material Design 3) |
|---|---|
| กว้างน้อยกว่า 600 (มือถือ) | หน้าต่างเต็มจอ (`Dialog.fullscreen`) |
| กว้าง 600 ขึ้นไป (แท็บเล็ต) | แผงลอยเลื่อนเข้าจากขวา กว้าง 400 (modal side sheet) ยังเห็นโน้ตด้านซ้าย กดพื้นที่ว่างเพื่อปิด |

ปิดแผงแล้วเปิดใหม่ **บทสนทนาและการเลือกแนบ/ไม่แนบโน้ตยังอยู่** จนกว่าจะออกจากหน้าแก้ไข

### 2.2 หน้าแชท

- **หน้าว่าง:** คำแนะนำ 3 อันกดแล้วส่งทันที (ช่วยผู้ใช้ครั้งแรก และใช้เป็นงานใน Usability Testing ได้)
- **ฟองข้อความ:** ผู้ใช้ชิดขวาสี `primaryContainer` / AI ชิดซ้ายสี `surfaceContainerHigh` (สีจาก theme ทั้งหมด)
- **คำตอบทยอยขึ้นทีละส่วน** (streaming) ระหว่างรอแสดง "กำลังคิด…" ถ้าผู้ใช้เลื่อนขึ้นไปอ่านระหว่างที่ AI ตอบ หน้าจอจะไม่ดึงกลับลงล่าง
- **คำตอบแสดงเป็น Markdown** และบล็อกโค้ดในคำตอบแสดงเป็นการ์ด:
  - **` ```mermaid `**: การ์ดไดอะแกรม ระหว่างที่ AI ยังพิมพ์แสดงเป็นโค้ด พอตอบจบแสดงเป็น**ภาพ** (ใช้ `MermaidDiagramView` เดิม) มีปุ่มสลับ **ภาพ / โค้ด** และปุ่ม **คัดลอก** ที่คัดลอกพร้อมรั้ว ` ```mermaid ` วางในโน้ตแล้วเป็นผังทันที
  - **ภาษาอื่น** (` ```dart `, ` ```python `, ` ``` ` ฯลฯ): การ์ดโค้ดมีชื่อภาษา ปุ่ม **คัดลอก** (คัดลอกโค้ดล้วน ไม่มีรั้ว) และเลื่อนซ้ายขวาได้ถ้าบรรทัดยาว
  - โค้ดในบรรทัด เช่น `print()` แสดงตามปกติ ไม่เป็นการ์ด
  - กดคัดลอกแล้วไอคอนเปลี่ยนเป็นเครื่องหมายถูก 2 วินาที (ไม่ใช้ SnackBar เพราะจะโดนหน้าต่างแชทบัง)
- **แถบความเป็นส่วนตัว** เปลี่ยนตามสถานะการแนบโน้ต:
  - แนบอยู่: "ข้อความที่พิมพ์และโน้ตที่แนบจะถูกส่งไปประมวลผลที่ Google Gemini"
  - ไม่แนบ: "ข้อความที่พิมพ์จะถูกส่งไปประมวลผลที่ Google Gemini · AI ไม่ได้อ่านโน้ตของคุณ"
- ปุ่มล้างบทสนทนา, แถบ error สี `errorContainer`
- **ข้อความเตือนใต้ช่องพิมพ์:** "Gemini เป็น AI และอาจตอบผิดพลาดได้ ควรตรวจสอบข้อมูลสำคัญ" แสดงตลอด ให้ผู้ใช้ตรวจคำตอบก่อนเชื่อ
- **จำกัดข้อความ 2000 ตัวอักษร** นับตามตัวอักษรที่เห็น (ภาษาไทยที่มีสระบน/ล่างไม่ถูกนับเกิน) ถ้ายาวเกิน ข้อความยังอยู่ในช่องพิมพ์ให้แก้ต่อ วางข้อความยาวลงช่องพิมพ์จะถูกตัดที่ 2000 (ถ้าต้องการให้ AI อ่านข้อความยาว ให้ใส่ในโน้ตแล้วแนบแทน)

### 2.3 แนบโน้ตให้ AI อ่าน

- **เปิดแชตแล้วแนบโน้ตที่เปิดอยู่ให้ทันที** แสดงเป็นชิป (`InputChip` ไอคอน `description_outlined`) เหนือช่องพิมพ์ ข้อความ "AI จะอ่าน: ชื่อโน้ต.md"
- **การเปิดแชตไม่ได้ส่งอะไรออกไป** โน้ตถูกส่งเมื่อผู้ใช้กดส่งข้อความเท่านั้น
- **กด x ที่ชิป** = ไม่แนบ ชิปเปลี่ยนเป็นปุ่ม "แนบโน้ตนี้" (`ActionChip` ไอคอน `attach_file`) ตำแหน่งเดิม ระบบจำค่านี้ไว้ ปิดแล้วเปิดแชตใหม่ก็ยังไม่แนบ จนกว่าผู้ใช้จะกดแนบเอง
- **ชิปอยู่ตลอดหลังส่ง:** ทุกข้อความที่ส่งระหว่างที่ชิปแสดงอยู่จะแนบโน้ตไปด้วย ถามต่อได้ว่า "แล้วข้อ 2 ล่ะ" AI ยังเห็นโน้ต
- **อ่านโน้ตตอนกดส่ง** จึงได้เนื้อหาล่าสุดบนจอ **รวมส่วนที่ยังไม่ได้บันทึก**
- **โน้ตว่าง** (หรือมีแต่ช่องว่าง) ไม่มีทั้งชิปและปุ่มแนบ
- **ข้อความที่ส่งตอนแนบโน้ต** มีป้ายเล็ก "แนบ: ชื่อโน้ต.md" บนฟอง เลื่อนย้อนดูได้ว่าคำตอบไหน AI อ่านโน้ตแล้ว
- **โน้ตยาวเกิน** (เกิน 1,000,000 ตัวอักษร หรือนับ token จริงแล้วเกิน 200,000 โน้ตทั่วไปไม่มีวันถึง): ไม่ส่ง แสดง "โน้ตยาวเกินไปสำหรับผู้ช่วย AI กด x ที่ชื่อโน้ตเพื่อส่งโดยไม่แนบ" ข้อความยังอยู่ในช่องพิมพ์ (เหตุผลในหัวข้อ 5.1)

## 4. การไหลของข้อมูล

```
แอปเปิด

ผู้ใช้กดปุ่ม AI
  → _openAssistant()            สร้าง AssistantChatController ครั้งแรก (เก็บไว้ในหน้า)
                                พร้อม documentProvider: () => AiDocumentContext(ชื่อ, เนื้อหา ของ _workspace.document)
  → showAssistantChat()         เลือก fullscreen / side sheet ตามความกว้างจอ
  → AssistantChatPanel          แสดงชิปตาม controller.isNoteAttached (ยังไม่ส่งอะไร)
                                ผู้ใช้พิมพ์แล้วกดส่ง
  → AssistantChatController.send()
       ตรวจ: ว่าง? ยาวเกิน 2000 (นับตัวอักษรที่เห็น)? กำลังตอบอยู่?
       document = แนบอยู่ ? เรียก documentProvider ตอนนี้ (โน้ตว่าง = null) : null
       ตรวจ: โน้ตยาวเกิน 1,000,000? → แจ้ง error ไม่ส่ง
       เพิ่มข้อความผู้ใช้ (เก็บแค่ชื่อโน้ตใน attachedNoteTitle ไม่เก็บเนื้อหา)
       ตัดประวัติเหลือ 20 ข้อความล่าสุด
  → AiAssistant.sendMessage(text, history, document)
  → FirebaseAiAssistant
       ตรวจโน้ตยาวเกินซ้ำ (ด่านสุดท้าย)
       buildSystemPrompt(hasDocument)   เลือกข้อความระบบแบบมี/ไม่มีโน้ต
       buildGeminiHistory()     กรองให้ผู้ใช้/AI สลับกัน
       buildUserPrompt()        <note> ชื่อ + เนื้อหา </note> ตามด้วยคำถาม
       chat.sendMessageStream()
         → firebase_ai ขอ App Check token ──→ Firebase AI Logic ──→ Gemini
  ← คำตอบทีละชิ้น (Stream<String>) ← controller ต่อข้อความ ← หน้าจอวาดใหม่
```

**เนื้อหาโน้ตถูกส่งเฉพาะในข้อความที่แนบเท่านั้น** ประวัติแชท (`history`) มีแค่ข้อความที่พิมพ์ จึงไม่ส่งโน้ตซ้ำในทุกรอบ และ AI ไม่เห็นโน้ตฉบับเก่า

**ถ้าผิดพลาด:** `FirebaseAiAssistant` แปลง error เป็น `AiAssistantException` ข้อความไทย controller แสดงในแถบ error แล้ว**ถอยกลับ** เอาทั้งคำถามและคำตอบที่ไม่จบออกจากรายการ (`send()` คืน `false`) หน้าจอคืนข้อความเข้าช่องพิมพ์ให้กดส่งซ้ำได้ สถานะการแนบโน้ตไม่เปลี่ยน

การแปลงอยู่ในฟังก์ชัน `aiErrorToException()` ที่เดียว (เช็กตามลำดับในตาราง):

| error | ข้อความที่ผู้ใช้เห็น | สาเหตุที่เคยเจอ |
|---|---|---|
| `QuotaExceeded` | "ใช้ผู้ช่วย AI ครบโควตาแล้ว รอสักครู่แล้วลองใหม่ ถ้ายังไม่ได้ แปลว่าโควตาของวันนี้หมด..." | ชนลิมิตต่อนาทีหรือต่อวัน (หัวข้อ 7.6) |
| `FirebaseAIException` อื่น | "ผู้ช่วย AI ไม่พร้อมใช้งานชั่วคราว..." | เซิร์ฟเวอร์ตอบกลับมาว่าไม่ได้ |
| `FirebaseException` ของ `firebase_app_check` | "ยืนยันความปลอดภัยของแอปไม่สำเร็จ..." | debug token ไม่ได้ลงทะเบียน, Play Integrity ไม่ผ่าน |
| `Exception` อื่น | "เชื่อมต่อผู้ช่วย AI ไม่สำเร็จ ตรวจสอบอินเทอร์เน็ต..." | เน็ตหลุด |
| (ไม่มี error แต่คำตอบว่าง) | "AI ไม่ได้ส่งคำตอบกลับมา ลองถามใหม่หรือเปลี่ยนคำถาม" | เช่น คำถามโดน safety filter ของ Gemini ตัดสินใน controller |
| (ตรวจในแอป) โน้ตยาวเกิน | "โน้ตยาวเกินไปสำหรับผู้ช่วย AI กด x ที่ชื่อโน้ตเพื่อส่งโดยไม่แนบ" | ตัวอักษรเกิน: ตรวจใน controller ก่อนส่ง / token เกิน: `countTokens` ก่อนส่ง (ไม่ใช้โควตา Gemini) |

`QuotaExceeded` เป็นลูกของ `FirebaseAIException` จึงต้องเช็กก่อน แพ็กเกจสร้าง `QuotaExceeded` เมื่อข้อความจากเซิร์ฟเวอร์มีคำว่า "quota" ซึ่งรวมทั้งโควตาต่อนาทีและต่อวัน แยกกันไม่ได้ ข้อความจึงครอบคลุมทั้งสองกรณี

**log:** `describeAiError()` พิมพ์แค่ชนิดของ error หรือ `plugin/code` ของ Firebase เช่น `AI request failed: firebase_app_check/unknown` หรือ `AI request failed: QuotaExceeded` ไม่พิมพ์ข้อความผู้ใช้ เนื้อหาโน้ต หรือข้อความ error เต็ม ถ้าต้องดูข้อความเต็มจริง ๆ ให้แก้ชั่วคราวแล้ว**แก้กลับก่อน commit ทุกครั้ง**

**ถ้าออกจากหน้าแก้ไขระหว่าง AI กำลังตอบ:** `dispose()` ของหน้าเรียก `_assistantChat?.dispose()` ซึ่งยกเลิกการรับคำตอบทันที ไม่มีการเชื่อมต่อค้างในพื้นหลัง

| **พารามิเตอร์ `assistant` ค่าเริ่มต้น `const FirebaseAiAssistant()`** | หน้าแก้ไขถูกสร้างจาก 4 จุดในไฟล์ของเพื่อน ใช้ค่าเริ่มต้นทำให้ปุ่มขึ้นทุกหน้าโดยไม่ต้องแก้ไฟล์เหล่านั้น ส่ง `null` เพื่อซ่อนปุ่มได้ |
| **side sheet แบบลอย ไม่ใช่แผงแทรกในหน้า** | ไม่ต้องรื้อโครง `build()` ของหน้าแก้ไข (ไฟล์ที่ทุกคนแก้) และเป็นรูปแบบที่ MD3 มี |
| **ใช้ App Check จาก `main.dart` (#33) ไม่ตั้งเอง** | มีจุดตั้งค่าที่เดียว เราไม่ต้องแตะ `main.dart` ของทีม |
| **`Completer` ใน `send()`** | ให้ `dispose()` ยกเลิก subscription และปลด `send()` ได้ทันที |
| **นับความยาวข้อความตามตัวอักษรที่เห็น (`characters`)** | ช่องพิมพ์นับแบบนี้ ถ้า controller นับ `String.length` ภาษาไทยที่มีสระบน/ล่างจะนับเกิน |
| **ล้างช่องพิมพ์เฉพาะเมื่อ controller รับข้อความ และคืนข้อความถ้าตอบไม่สำเร็จ** | ถ้าข้อความถูกปฏิเสธหรือเน็ตหลุด/โควตาหมด ผู้ใช้ไม่ต้องพิมพ์ใหม่ |
| **ตอบไม่สำเร็จแล้วถอยกลับทั้งคู่ (คำถาม + คำตอบที่ไม่จบ)** | คำตอบที่ขาดกลางทางถ้าเก็บไว้ จะถูกส่งเป็นประวัติรอบหน้า |
| **คำตอบว่างถือว่าไม่สำเร็จ** | สตรีมจบโดยไม่มีข้อความ (เช่น safety filter) ไม่มี error มาบอก ถ้านับว่าสำเร็จ ผู้ใช้จะเห็นฟองว่างโดยไม่รู้สาเหตุ |
| **`messages` คืน `UnmodifiableListView`** | ห่อ list เดิมไว้ ไม่คัดลอกทุกครั้งที่เรียก ภายนอกยังแก้ไม่ได้ |
| **ไม่ cache `GenerativeModel`** | สร้างใหม่ทุกครั้งเป็นแค่ object ไม่ได้ต่อเน็ต และทำให้เปลี่ยน system prompt ตามว่าแนบโน้ตหรือไม่ได้ทุกข้อความ |
| **Mermaid แสดงเป็นโค้ดระหว่าง AI พิมพ์ แล้วค่อยวาดตอนจบ** | โค้ดที่ยังพิมพ์ไม่จบทำให้ตัววาดผังขึ้น Syntax error `MarkdownBody` ใช้ `key: ValueKey(isStreaming)` เพราะมันแปลงใหม่เฉพาะตอน `data` เปลี่ยน |
| **`buildGeminiHistory()` ส่งเฉพาะคู่ที่สมบูรณ์** | ถ้า AI เคยตอบพลาด ประวัติจะมีข้อความผู้ใช้ติดกัน 2 อัน Gemini อาจปฏิเสธคำขอ |
| **ไม่แสดง error ดิบของ Google, `on Exception` ไม่ใช่ `catch` เปล่า, แยก `aiErrorToException()`** | ไม่หลุดรายละเอียดภายใน ไม่กลืนบั๊ก และ test ข้อความ error ได้ทุกกรณีโดยไม่เรียก Gemini จริง |

### 5.1 การตัดสินใจของการแนบโน้ต

| การตัดสินใจ | เหตุผล |
|---|---|
| **แนบให้ทันทีที่เปิดแชต (ทีมเลือก)** แต่ต้องเห็นชิปเสมอและกด x ได้ก่อนส่ง | ใช้ง่ายกว่าต้องกดแนบทุกครั้ง ยังปลอดภัยเพราะการเปิดแชตไม่ส่งอะไร และผู้ใช้เห็นชัดว่าโน้ตจะถูกส่ง กฎที่ใช้แทน "ห้ามส่งถ้าผู้ใช้ไม่กด" คือ **"มีชิปเมื่อไหร่ต้องส่งโน้ต ไม่มีชิปต้องไม่ส่ง และผู้ใช้เอาออกได้ก่อนส่ง"** |
| **ชิปอยู่ต่อหลังส่ง (ส่งโน้ตทุกข้อความจนกว่าจะกด x)** | ถามต่อเนื่องได้ และ AI เห็นโน้ตฉบับล่าสุดเสมอ ถ้าแนบแค่ข้อความแรก AI จะ "ลืม" โน้ตในคำถามถัดไป ผู้ใช้จะงง |
| **สถานะการแนบและ `documentProvider` อยู่ใน controller ไม่ใช่หน้าจอ** | กฎข้างบนอยู่ที่เดียว ชิปบนจอกับสิ่งที่ส่งจริงคำนวณจากเงื่อนไขเดียวกัน (`_noteAttached` + `_currentNote()`) test ได้ด้วย unit test และจำค่าได้หลังปิดแผง (หน้าจอถูกสร้างใหม่ทุกครั้งที่เปิด) |
| **`documentProvider` เป็นฟังก์ชัน ไม่ใช่ค่าตายตัว** | controller อยู่ตลอดอายุหน้า แต่โน้ตถูกแก้ตลอด เรียกฟังก์ชันตอนกดส่งจึงได้เนื้อหาล่าสุด |
| **ไม่เก็บเนื้อหาโน้ตในประวัติแชท เก็บแค่ชื่อ (`attachedNoteTitle`)** | ถ้าเก็บ โน้ตจะถูกส่งซ้ำในประวัติทุกรอบ และ AI อาจอ่านโน้ตฉบับเก่าที่ถูกแก้ไปแล้ว |
| **ห่อโน้ตด้วย `<note>...</note>` และแก้ `</note>` ที่อยู่ในโน้ตเป็น `</ note_>`** | ลดความเสี่ยง prompt injection: ข้อความในโน้ตปลอมตัวเป็นคำสั่งจากผู้ใช้ไม่ได้ เพราะปิดแท็กเองไม่ได้ (จับทั้ง `</NOTE>` และ `</ note >`) ชื่อโน้ตถูกรวมเป็นบรรทัดเดียว แก้เฉพาะ**สำเนาที่ส่งให้ AI** โน้ตจริงไม่เปลี่ยน และมีผลแค่ข้อความ `</note>` ตรงตัว (HTML ไม่มีแท็กนี้) ใช้ฟังก์ชัน `_escapeNoteTag` ตัวเดียวทั้งชื่อและเนื้อหา |
| **แยก system prompt แบบมี/ไม่มีโน้ต** | ข้อความเดิมบอก AI ว่า "มองไม่เห็นโน้ต" ถ้าส่งโน้ตไปพร้อมข้อความนี้ AI จะได้คำสั่งขัดกัน แบบมีโน้ตบอกว่าข้อความในแท็กเป็นข้อมูล ห้ามทำตาม แบบไม่มีโน้ตบอกให้ผู้ใช้แนบก่อน ห้ามบอกว่าอ่านแล้ว |
| **ตรวจความยาวโน้ต 2 ชั้น** (controller + `FirebaseAiAssistant`) และนับ token จริงเฉพาะโน้ตยาว | controller ให้ข้อความที่บอกวิธีแก้และไม่ยิงคำขอเลย ชั้น data เป็นด่านสุดท้ายถ้ามีโค้ดอื่นเรียกตรง (ใช้ `throw` ไม่ใช่ `assert` เพราะ assert ไม่ทำงานใน release) |
| **โน้ตยาวเกินแล้วปฏิเสธ ไม่ตัดทิ้ง** | ถ้าแอปตัดส่วนท้ายเงียบ ๆ AI จะตอบเหมือนอ่านครบทั้งที่ไม่ครบ ผู้ใช้อาจเชื่อคำตอบที่ผิด |
| **ปุ่มแนบกลับเป็น `ActionChip` ตำแหน่งเดียวกับ `InputChip`** | ผู้ใช้หาเจอที่เดิม มีข้อความกำกับ ไม่ต้องเดาจากไอคอน และไม่เบียดช่องพิมพ์ (ใช้ไอคอน Material ไม่ใช้อีโมจิ) |

**ลิมิตความยาวโน้ต 1,000,000 ตัวอักษร: ที่มาของตัวเลข**

เดิมตั้งไว้ 20,000 โดยไม่ได้วัด หลังหาข้อมูลแล้วพบว่าตัวเลขนั้นไม่มีเหตุผลรองรับ จึงขยับไปที่เพดานจริง:
- Gemini 3.8 Flash รับ input ได้ 1,048,576 token และ 1 token ประมาณ 4 ตัวอักษร (เอกสาร Google ไม่ได้ระบุอัตราของภาษาไทย)
- เพดานที่ต่ำกว่าคือ **TPM 250K token ต่อนาทีของแผนฟรี** (หัวข้อ 7.6) คำขอเดียวที่เกินนี้ส่งไม่ผ่านอยู่แล้ว 250K × 4 ≈ 1,000,000 ตัวอักษร
- **RPD นับจำนวนครั้ง ไม่ได้นับความยาว** โน้ตยาวจึงไม่ทำให้โควตารายวันหมดเร็วขึ้น

ลิมิตนี้จึง**ไม่ได้มีไว้ประหยัด** แต่มีไว้ให้ผู้ใช้เห็นข้อความที่บอกสาเหตุชัดเจน ถ้าไม่ตรวจเอง โน้ตที่ใหญ่เกินจะได้ error จาก Gemini ซึ่งแอปแปลงได้แค่ "ไม่พร้อมใช้งาน" หรือ "ครบโควตา" ผู้ใช้จะเข้าใจผิด

**ภาษาไทยกับ token (แก้ตามรีวิว):** ภาษาไทยอาจใช้ token ต่อตัวอักษรมากกว่าภาษาอังกฤษ ลิมิตตัวอักษรอย่างเดียวจึงไม่พอ โน้ตที่ยาวเกิน 50,000 ตัวอักษรจะถูกนับ token จริงด้วย `countTokens` ก่อนส่ง (ฟรี ไม่ใช้โควตา Gemini) ถ้าเกิน 200,000 token (`maxPromptTokens` เว้นที่ให้ system prompt และประวัติใต้ TPM 250K) จะแจ้ง "โน้ตยาวเกินไป" แทน error ทั่วไป ทำไมต่ำกว่า 50,000 ไม่ต้องนับ: 1 ตัวอักษรใช้ได้ไม่เกิน 4 token แม้ tokenizer แตกเป็นรายไบต์ (UTF-8 ยาวสุด 4 ไบต์) 50,000 × 4 = 200,000 จึงไม่มีทางเกิน โน้ตทั่วไปจึงไม่มีคำขอเพิ่ม

ไม่ใส่คำเตือนแบบ "โน้ตยาว AI อาจตอบผิด" เพราะไม่มีข้อมูลว่ายาวเท่าไหร่ถึงมีผล ใช้ข้อความเตือนทั่วไปใต้ช่องพิมพ์แทน (หัวข้อ 2.2)

ค่าคงที่อยู่ที่ `AiDocumentContext` (`maxContentLength`, `maxPromptTokens`, `tooLongMessage`) ที่เดียว test ทุกตัวอ้างค่าคงที่นี้ ถ้าจะปรับ (เช่น หลังวัด token ภาษาไทยด้วย `countTokens` ซึ่งฟรีและไม่ใช้โควตา) แก้บรรทัดเดียว ควรย้ายไปตั้งจาก Remote Config (หัวข้อ 8.1)

## 7. Firebase Console และการใช้งานจริง (สำคัญสำหรับคนดูแล Firebase และวันเทส)

### 7.1 การตั้งค่าปัจจุบัน

| ที่ | ค่า |
|---|---|
| AI Logic → ผู้ให้บริการ | **Gemini Developer API** (แผน Spark ฟรี ไม่ผูกบัตร) |
| AI Logic → AI monitoring | **ปิด** (อาจเก็บข้อความผู้ใช้และเนื้อหาโน้ตที่แนบไว้ใน log ควรตกลงกับทีมก่อนเปิด) |
| App Check → APIs → Firebase AI Logic | **Basic - Monitoring** / Replay protection: **Disabled** |
| App Check → Apps → mnote (android) → Play Integrity | SHA-256 2 ตัว (`ba:25:...` และ `2E:66:...`) |
| Play Integrity → Advanced settings | ไม่ติ๊ก `PLAY_RECOGNIZED`, ไม่ติ๊ก `LICENSED`, ระดับขั้นต่ำ **Device integrity** |
| debug token (android) | `Tablet SM-T735 (Faa)` |
| debug token (ios) | `pet` (iPad) |
| App Check → Apps → mnote (ios) | ไม่ได้ลงทะเบียน App Attest / DeviceCheck (หัวข้อ 7.5) |
| App Check ของ Firestore / Auth | **ไม่ได้แตะ** (Monitoring) |

**ห้ามเปิด Replay protection:** ต้องใช้ token แบบใช้ครั้งเดียว (limited-use) ซึ่งโค้ดไม่ได้ขอ ถ้าเปิด AI จะโดนบล็อกทุกเครื่อง

**ห้ามกด Enforce ของ Firestore / Auth ตอนนี้:** หน้า App Check ยังแสดงคำขอที่ไม่ผ่าน (Firestore unverified ~11%, Auth ~100% ณ 24 ต.ค. 2026) ถ้ากด เพื่อนบางคนจะล็อกอินหรือโหลดโน้ตไม่ได้ทันที

### 7.2 สิ่งที่ค้นพบจากการทดสอบจริง

1. **firebase_ai ไม่ส่งคำขอเลยถ้าขอ App Check token ไม่ได้ แม้ AI Logic ยังเป็นโหมด Monitoring** ทุกเครื่องต้องผ่าน App Check เสมอ
2. **หน้า App Check นับเฉพาะคำขอที่ไปถึงเซิร์ฟเวอร์** จึงอาจเห็น verified 100% ทั้งที่บางเครื่องใช้ไม่ได้
3. **เส้นตาย 2 พฤศจิกายน 2026:** Firebase จะบังคับ App Check กับ AI Logic (Console แสดงแถบแจ้งเตือนนี้) เพราะข้อ 1 ผลจริงจึง**เหมือนตอนนี้ทุกอย่าง**:
   - **Android:** ตั้งค่า Play Integrity ครบแล้ว (7.3) debug build ยังต้องลงทะเบียน debug token เหมือนเดิม (7.4)
   - **iOS:** ใช้ AI ได้**เฉพาะเครื่องที่ลงทะเบียน debug token** (7.5)

### 7.3 Play Integrity (แอป Android release)

แอป release ใช้ Play Integrity แทน debug token ต้องผ่าน 2 เงื่อนไข**พร้อมกัน**:

| เงื่อนไข | ทำไม | ถ้าไม่มี |
|---|---|---|
| SHA-256 ของ key ที่เซ็นแอป ลงทะเบียนใน Console | Firebase ตรวจว่าแอปเซ็นด้วย key ที่รู้จัก | `403 App attestation failed` |
| ปิด `PLAY_RECOGNIZED` | แอปเราไม่ได้ขึ้น Google Play จึงไม่มีทางผ่านข้อนี้ | `403 App attestation failed` ทุกครั้ง |

ทดสอบแล้ว: ลบ SHA-256 ออก → AI ใช้ไม่ได้, ใส่กลับ → ใช้ได้ (ต้องติดตั้งแอปใหม่เพื่อทิ้ง token เก่าที่ใช้ได้ 1 ชั่วโมง)

ใช้ระดับ **Device integrity** แทน `PLAY_RECOGNIZED` เพื่อยังกันโปรแกรมจำลอง เครื่องที่ root และสคริปต์ได้

**SHA-256 ผูกกับคอมที่ build ไม่ใช่เครื่องที่ใช้แอป:** ตอนนี้ทีมเซ็นแอป release ด้วย debug key ของแต่ละคอม (`android/app/build.gradle.kts` บรรทัด 35)
- ใครจะ build APK release ไปแจก ต้องเพิ่ม SHA-256 ของคอมตัวเองก่อน: `cd android && ./gradlew signingReport` → ค่า `SHA-256` ใต้ `Variant: release` → Console → Play Integrity → **Add another fingerprint** (**อย่าลบของคนอื่น**)
- หรือตกลงให้คนเดียวเป็นคน build APK
- ระยะยาว: Owner สร้าง release key ร่วมกันหนึ่งตัว (ไฟล์ key และรหัสผ่านเป็นความลับ ห้ามใส่ใน git)
- SHA-256 **ไม่ใช่ความลับ** แชร์ในทีมได้

### 7.4 debug token (นักพัฒนาที่ใช้ `flutter run`)

debug build ใช้ debug token ทุกเครื่องที่ `flutter run` แล้วจะใช้ AI ต้องลงทะเบียน token ของเครื่องนั้น:

**Android**
1. `flutter run` → เปิดแชท → ส่งข้อความ 1 ครั้ง (จะ error)
2. `adb logcat -d | grep DebugAppCheckProvider` → คัดลอกรหัสหลัง `Firebase App Check debug token:`

**iOS (บน Mac)**
1. เปิด `ios/Runner.xcworkspace` ใน Xcode → เลือก Simulator หรือเครื่องจริง → กด Run
2. ใน console ของ Xcode ค้น `App Check debug token` → คัดลอกรหัส

**ลงทะเบียน (ทั้งสองแพลตฟอร์ม)**
App Check → Apps → แถวของแพลตฟอร์มนั้น → **⋮** → **Manage debug tokens** → Add → ตั้งชื่อ `อุปกรณ์ (ชื่อคน)` → วาง token → Save
- **อย่ากด Generate token** (ใช้สำหรับ CI จะได้ token ที่ไม่ตรงกับเครื่อง)
- **อย่าวางในช่อง SHA-256 ของ Play Integrity**
- แอป iOS ไม่ต้องลงทะเบียน App Attest / DeviceCheck ก่อน และไม่ต้องมีบัญชี Apple Developer แบบเสียเงิน (ทดสอบแล้วบน iPad)

**debug token เป็นความลับ** ห้ามใส่ในโค้ด, README, PR หรือแชทกลุ่ม ถ้าล้างข้อมูลแอป ถอนการติดตั้ง หรือรีเซ็ต simulator จะได้รหัสใหม่และต้องลงทะเบียนอีกครั้ง

### 7.5 ใครใช้ AI ได้บ้าง

| แพลตฟอร์ม / build | ใช้ AI ได้ไหม | ต้องทำอะไร |
|---|---|---|
| Android `flutter run` (debug) | ได้ | ลงทะเบียน debug token ของเครื่องนั้น (7.4) |
| Android `flutter run --release` / APK release บนเครื่องจริง | **ได้ทุกเครื่อง** ไม่ต้องลงทะเบียน | ต้อง build จากคอมที่ใส่ SHA-256 ไว้แล้ว (7.3) |
| Android release บนโปรแกรมจำลอง | ไม่ได้ | ตั้งใจ: ไม่ผ่าน Device integrity |
| iOS `flutter run` / Xcode (debug) | **ได้เฉพาะเครื่องที่ลงทะเบียน debug token** | ลงทะเบียน debug token ในแถว mnote (ios) |
| iOS แบบ release / แอปที่แจกคนอื่น | **ไม่ได้** | ต้องลงทะเบียน App Attest / DeviceCheck ซึ่งต้องมีบัญชี Apple Developer แบบเสียเงิน ทีมยังไม่มี |

**iOS แจกไม่ได้เป็นข้อจำกัดของ Apple ไม่ใช่ของ AI:** ถ้าไม่มีบัญชี Apple Developer แบบเสียเงิน แอปทั้งตัวก็ติดตั้งลง iPhone ของคนอื่นไม่ได้อยู่แล้ว ถ้าอาจารย์ใช้ iPhone ให้ demo บนเครื่องของทีม

**แนะนำสำหรับวันเทส**
- คนที่แค่เทส ไม่ได้แก้โค้ด: ใช้ **APK release** (`flutter build apk --release` จากคอมที่ลงทะเบียน SHA-256 แล้ว)
- คนที่ต้อง `flutter run` เพื่อแก้โค้ด: ลงทะเบียน debug token ของเครื่องตัวเองล่วงหน้า
- APK ที่ CI สร้าง (`Build Android debug APK`) เป็น debug ใช้ AI ไม่ได้ถ้าไม่ลงทะเบียน token

### 7.6 โควตา (สำคัญ)

ลิมิตจริงของ `gemini-3.8-flash` ในแผนฟรีของโปรเจกต์ `mnote-8db27` (ดูจาก [AI Studio rate limit](https://aistudio.google.com/rate-limit) ณ 24 ต.ค. 2026):

| ลิมิต | ค่า | นับอะไร |
|---|---|---|
| RPM | **5 ครั้งต่อนาที** | จำนวนคำขอ |
| TPM | **250K token ต่อนาที** | token ขาเข้า (ข้อความ + ประวัติ + โน้ตที่แนบ) |
| RPD | **20 ครั้งต่อวัน** | จำนวนคำขอ ไม่ขึ้นกับความยาว |

- **ลิมิตนับรวมทั้งโปรเจกต์ ไม่ได้นับรายคน** ([เอกสาร](https://ai.google.dev/gemini-api/docs/rate-limits)) ทั้งทีมได้ 20 ข้อความต่อวันรวมกัน
- **RPD รีเซ็ตเที่ยงคืนเวลาแปซิฟิก** (ประมาณ 14:00 น. เวลาไทย และประมาณ 15:00 น. หลังสหรัฐฯ เลิกใช้เวลาออมแสงต้นเดือนพฤศจิกายน) "วันนี้" ของโควตาจึงเริ่มตั้งแต่บ่ายของวันก่อนตามเวลาไทย
- **ส่งติดกันเร็ว ๆ 5 ครั้งในนาทีเดียวจะชน RPM** หายเองภายในไม่ถึงนาที (เคยเจอระหว่างทดสอบ) เว้นประมาณ 15 วินาทีระหว่างข้อความเวลาทดสอบ
- พอชน ผู้ใช้เห็น "ใช้ผู้ช่วย AI ครบโควตาแล้ว..." แอปไม่พัง และใน log เห็น `AI request failed: QuotaExceeded`
- ดูการใช้งานได้ที่หน้า rate limit ของ AI Studio เลือกโปรเจกต์ **Mnote** และช่วงเวลา **1 Day** (มุมมอง 28 วันแสดงค่าสูงสุดเก่า อาจเข้าใจผิดว่าโควตาวันนี้หมด) **ในหน้านั้นห้ามกด Create API key และ Set up billing**
- **20 ครั้งต่อวันไม่พอสำหรับ Usability Testing หลายคน** ควรวางแผนจำนวนข้อความล่วงหน้า หรือพิจารณาเปลี่ยนโมเดล (หัวข้อ 8.1)
- **ห้ามกด Upgrade เป็น Blaze** เพื่อแก้โควตาโดยไม่ได้ตกลงกับทีม

## 8. ต่อยอด

### 8.1 Remote Config: โมเดล ระดับการคิด และลิมิตโน้ต (PR ถัดไป)

ตอนนี้ค่าเหล่านี้อยู่ในโค้ด เปลี่ยนแล้วต้องออกแอปใหม่ ควรย้ายไปตั้งจาก Firebase Remote Config (จะเป็น Firebase บริการที่ 4):

| ค่า | ตอนนี้ | ทำไมควรปรับได้ |
|---|---|---|
| `FirebaseAiAssistant.modelName` | `gemini-3.8-flash` (RPD 20) | สลับโมเดลที่โควตามากกว่าช่วง Usability Testing ได้ ต้องดูลิมิตของโมเดลนั้นในโปรเจกต์ก่อน |
| ระดับการคิด (`ThinkingConfig.withThinkingLevel`) | ไม่ได้ตั้ง (ค่าเริ่มต้น MEDIUM) | **AI ตอบช้าเพราะการคิดเป็นหลัก** 3.8 Flash รองรับ low / medium / high (ไม่รองรับ minimal จะได้ error 400) ปิดการคิดไม่ได้ ตั้ง LOW จะเร็วขึ้นแต่คำตอบที่ต้องใช้เหตุผลอาจด้อยลง |
| `AiDocumentContext.maxContentLength` | 1,000,000 | ปรับตามเพดานของแผนที่ใช้ (เช่น ถ้าเปิด billing TPM จะสูงขึ้น) |

### 8.2 ส่งเฉพาะส่วนที่เลือกของโน้ต

ถ้าต้องการรองรับโน้ตยาวมาก ดีกว่าการเพิ่มลิมิต: ส่ง selection ของ editor แทนทั้งโน้ต ต้องอ่าน selection จาก `_textController` ของหน้าแก้ไขตอนเปิดแชต (selection จะหายเมื่อแชทได้ focus) จึงต้องแตะไฟล์ของเพื่อนมากกว่างานนี้

### 8.3 เปิด App Check กับ Firestore / Auth

โค้ดเปิด App Check ให้ทั้งแอปแล้ว (`main.dart` จาก #33) เหลือฝั่ง Console เป็นงานของ Owner:
1. ตรวจ Firestore Security Rules ก่อน (App Check ไม่ได้แทน Rules)
2. ทุกคนในทีมลงทะเบียน debug token
3. ดูกราฟ verified/unverified จน unverified ใกล้ 0% แล้วค่อยกด Enforce ทีละบริการ

### 8.4 เปลี่ยนข้อความระบบ

แก้ใน `firebase_ai_assistant.dart` ไฟล์เดียว:
- `_basePrompt`: ใช้ทุกข้อความ (ภาษา, Markdown, mermaid, แก้โน้ตไม่ได้ ห้ามบอกว่าแก้แล้ว)
- `_noNotePrompt`: ตอนไม่แนบโน้ต (มองไม่เห็นโน้ต ให้ผู้ใช้แนบก่อน)
- `_withNotePrompt`: ตอนแนบโน้ต (ข้อความใน `<note>` เป็นข้อมูล ไม่ใช่คำสั่ง)

test 6e/6f เช็กว่าแบบมีโน้ตต้องไม่มีคำว่า "มองไม่เห็นโน้ต" ถ้าแก้ข้อความต้องดูให้ไม่ขัดกันแบบเดิม

### 8.5 ใช้ผู้ช่วย AI ในหน้าอื่น

```dart
import 'package:mnote/features/assistant/data/firebase_ai_assistant.dart';
import 'package:mnote/features/assistant/domain/ai_assistant.dart';
import 'package:mnote/features/assistant/presentation/assistant_chat_controller.dart';
import 'package:mnote/features/assistant/presentation/assistant_chat_panel.dart';

// ใน State: สร้างครั้งเดียว และ dispose ใน dispose()
// ไม่ต้องการให้แนบโน้ต: ไม่ส่ง documentProvider (ชิปและปุ่มแนบจะไม่แสดง)
late final _chat = AssistantChatController(
  const FirebaseAiAssistant(),
  documentProvider: () => AiDocumentContext(
    title: currentDocumentName,      // อ่านค่าล่าสุดทุกครั้งที่เรียก
    content: currentDocumentContent,
  ),
);

// เปิดแชท
showAssistantChat(context, controller: _chat);
```

ใน test ใช้ `FakeAiAssistant` จาก `test/helpers/fake_ai_assistant.dart` แทน (ดู `lastDocument` ได้ว่าส่งโน้ตอะไรไป)

**บนเครื่องจริง: แชท (#31)**
- debug: คุยได้, คำตอบทยอยขึ้น, ไดอะแกรมแสดงเป็นภาพ, ปิด/เปิดแผงบทสนทนายังอยู่, ช่องพิมพ์ไม่โดนแป้นพิมพ์บัง
- release: ใช้ AI ได้หลังตั้งค่า Play Integrity ลบ SHA-256 แล้วใช้ไม่ได้ ใส่กลับแล้วใช้ได้
- iPad (iOS, debug): ลงทะเบียน debug token แล้วใช้ได้

**ทดสอบบนเครื่องเพิ่ม (ค้างจาก #31) ผ่าน:** การ์ดโค้ดคัดลอกได้โค้ดล้วน, Mermaid แสดงเป็นโค้ดระหว่างสตรีมแล้วเปลี่ยนเป็นภาพตอนจบ, เลื่อนขึ้นอ่านระหว่าง AI ตอบโดยไม่ถูกดึงลง

**ยังไม่ได้ทดสอบบนเครื่อง:** ข้อความโควตาแบบใหม่ (ต้องรอเจอเอง ไม่ควรตั้งใจใช้โควตาให้หมด)

**ไม่ได้ทดสอบอัตโนมัติ:** การเรียก Gemini จริงและพฤติกรรมของ AI (กรณี 4 และ 7) ต้องทดสอบด้วยมือ กรณี 7 ทดสอบรอบเดียว ผลอาจต่างไปตามข้อความที่ใช้
